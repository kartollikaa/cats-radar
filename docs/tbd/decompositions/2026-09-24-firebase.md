## Slice details

### Slice F1 — Application id `com.kartollika.catsradar`
- **In scope:** `applicationId` in the application convention plugin; parent spec §8 and §10;
  `releasing.md` (installs beside the old app; backup round trip); `app-shell.md` if it names the id;
  this spec and this map.
- **Out of scope:** Kotlin packages and module namespaces (stay `dev.catsradar.*`); intent action names.
- **Ships safely because:** manifest authorities already follow `${applicationId}`; no data format
  records the id.
- **Cleanup owed:** none.

### Slice F2 — Crash reports to Crashlytics
- **In scope:** google-services and Crashlytics Gradle plugins and the Firebase BoM in the catalogue; a
  `catsradar.firebase` convention plugin applied by `:app`; `app/google-services.json`; the
  `build_type` custom key at process start; non-fatals from the startup repairs and every worker's
  catch-all; `analytics.md` (Crashlytics part), `map.md`, `README.md` index, parent spec §6.5.
- **Out of scope:** Analytics SDK and every event (F3a/F3b).
- **Ships safely because:** reporting is write-only; a missing network only delays reports.
- **Cleanup owed:** none.

### Slice F3a — Analytics port and screen views
- **In scope:** `Analytics`, `AnalyticsEvent` (screen view only), `AnalyticsScreen` in `:domain`; the
  encoding and its limits test in `:data/commonMain`; `FirebaseAnalyticsReporter` in `:data/androidMain`;
  Koin binding; `build_type` user property; `screen_view` from the back stack with the
  `NavKey → AnalyticsScreen` mapping tested; manifest: advertising id and ad personalisation off,
  `AD_ID` permission removed, automatic screen reporting off; the Konsist `com.google.firebase` rule;
  `analytics.md`, `module-structure.md`, `static-analysis.md`, parent spec §6.1.
- **Out of scope:** events from use cases (F3b).
- **Ships safely because:** logging is fire-and-forget and never fails navigation.
- **Cleanup owed:** none.

### Slice F3b — Product events
- **In scope:** the remaining catalogue events and their encoding; each use case in the spec's §5 table
  takes `Analytics` and logs after its write, with a success and a failure test; Koin constructor
  wiring; `analytics.md`.
- **Out of scope:** new events beyond the spec's catalogue.
- **Ships safely because:** the event is logged after the write it reports, so logging cannot change
  what is stored.
- **Cleanup owed:** none.

## Decision log

- 2026-09-24: owner asked to connect the app to Firebase for crash reports and product analytics.
  Decisions: application id `com.kartollika.catsradar` (Kotlin packages unchanged); config committed;
  always on with no switch; every build reports, tagged by build type. Events are logged by use cases
  rather than Stores so the widget, the notification and workers are covered by the same call.

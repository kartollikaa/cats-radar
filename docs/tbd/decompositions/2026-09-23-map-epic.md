## Slice details

### Slice M1 — Map tab with your cats
- **In scope:** `maplibre-compose` and one Android render runtime in the catalog; OpenFreeMap vector
  styles, the light or dark one with the theme; the `INTERNET` permission; a `Map` tab and `NavKey`;
  `MapStore`/`MapState`/mapper building one point per non-deleted encounter that has coordinates, with
  a coat token; a circle layer coloured per coat; the camera fitted to the points once; the attribution
  the tiles require; an empty state instead of a map when no cat has a location, and a notice when the
  map cannot load. The app is launched on the 16 KB-page emulator, because the renderer ships native
  code no gate here inspects.
- **Out of scope:** tapping a dot (M2), clustering (M2), routes (M3).
- **Ships safely because:** a complete, read-only screen over data that already exists.

### Slice M2 — A cat on the map opens it
- **In scope:** `MapIntent.CatsTapped(ids)`: one cat opens `EncounterDetail` above the Map tab,
  several open a list of that spot; clustering with a count, expanding on tap, and a cluster that
  never comes apart opening as that list.
- **Ships safely because:** additive interaction on M1's screen.

### Slice M3 — An outing's route
- **In scope:** an outing header in the Encounters list gains "On the map"; the Map tab opens focused
  on that outing, its cats joined in time order by a line; leaving the focus returns to all cats.
- **Out of scope:** real GPS tracks (M5, M6).
- **Ships safely because:** additive; the outing grouping is the one the list already uses.

### Slice M4 — Walk tracks, stored
- **In scope:** `Walk(id, startedAt, endedAt?)` and `TrackPoint(walkId, at, lat, lon, accuracy)`
  entities, Room migration with an exported schema and a migration test, repository, `StartWalk`,
  `EndWalk`, `RecordTrackPoint` (drops points that are too inaccurate or too close to the last one),
  `trackLengthMeters` by great-circle distance, tests.
- **Ships safely because:** nothing calls it yet.

### Slice M4b — Walks in backups
- **In scope:** walks and track points in the archive, a format version bump that an older app
  refuses cleanly, merge rules (a walk is kept by `id`, the later `updatedAt` wins, points follow
  their walk), round-trip test. Two cases the rules must settle: appending a point leaves the
  walk's `updatedAt` alone, so two archives of one walk can tie while holding different routes; and
  an archive can carry a walk that is still on while another is on here, which one-walk-at-a-time
  forbids.
- **Ships safely because:** nothing records walks until M5, so the format is ready before there is
  anything to lose.

### Slice M5 — Walk tracks, recorded
- **In scope:** turning walking mode on starts a walk and, when location is allowed, a foreground
  service of type `location` that records track points and carries the walking notification; turning it
  off, or the notification's stop, ends both; process death and reboot leave a walk ended rather than
  open for ever, at its last point rather than at whenever the app next runs, and a fix with no
  accuracy (Android reports 0) is not taken as a perfect one.
- **Out of scope:** showing the track (M6).
- **Ships safely because:** without location permission a walk behaves exactly as today.

### Slice M6 — Walks on the map, and cats per km
- **In scope:** a walk's track as a line on the map, its cats as dots on it; distance and cats per km in
  Statistics next to cats per hour.

### Slice M7 — Heatmap and coat filter
- **In scope:** a heatmap layer weighted by encounter count, toggled from the map; a coat filter
  applying to dots, clusters and heat.

## Decision log

- 2026-09-23: **M4 split.** Backups carry every live row the app keeps, so walks must travel in them before anything records a walk: the archive format and its merge rules are M4b, between the tables (M4) and the recording (M5). Together they were past a review-sized PR.
- 2026-09-23: **mapped.** Owner's instruction after v1: proceed to the Map epic. Rulings, each
  recorded so it can be reversed:
  - **Tiles from OpenFreeMap**, vector tiles built from OpenStreetMap data, free with no key,
    account or cookies — what spec §9 asks for with "OSM tiles, no API key or billing".
    OpenStreetMap's own raster tile server is not meant to be an app's default. Cost if wrong:
    one style URL.
  - **The app goes online for the first time.** Until now it declared no `INTERNET` permission,
    because geocoding runs through the platform. Tiles need it, and a tile request tells the tile
    server which area is being looked at. Documented in the feature doc rather than hidden.
  - **`maplibre-compose` over the MapLibre Android SDK view.** It is Compose-native and
    multiplatform, the same component the spec wants to reuse for iOS. Cost if wrong: M1's map
    composable, since the layers are GeoJSON either way.
  - **A tracked walk does not redefine an outing.** This keeps the 2026-09-22 ruling in the v1 map:
    outings stay derived by `SessionSplitter`. A walk adds a track and a distance for the cats
    inside its window. Cost if wrong: M6's statistics join, not the data model.
- 2026-09-23: **M1 with no located cat shows an empty state, not a default map.** A map of nowhere in
  particular says nothing, and it would fetch tiles before there is anything to show. Cost if wrong:
  the empty branch of `MapScreen`.
- 2026-09-23: **M2 lists a spot's cats.** The outing backfill gives every cat of a walk the same fix, so
  their cluster never comes apart however far the map zooms. Tapping it lists those cats with the
  Encounters rows, rather than stacking dots of which only the top one can be tapped. Cost if wrong:
  `MapSpotSheet` and the spot in `MapState`.
- 2026-09-23: **M3 hands an outing to the Map tab through `MapFocusRequest`.** The tab's key is shared with
  the bottom bar, so it carries no outing; a request that the map consumes on arrival works like the
  widget's `CameraRequest`. Back on a focused map returns to every cat rather than leaving the tab.
  Cost if wrong: the handoff and one `BackHandler`.
- 2026-09-23: **M4b's two open cases.** Routes are merged, not replaced: a point is one walk at one moment, so
  the two archives of one walk that tie on `updatedAt` still give the longer route. A walk still on in an
  archive arrives ended at its last point, unless it is the walk on here, which keeps one walk at a time.
  Duplicates are dropped in the merge rather than by a unique index, which keeps M4's version-2 schema
  as it is. Cost if wrong: `WalkMerge`.
- 2026-09-23: **M5's rulings.** The stored flag stays what the controls write, and the walk follows it
  as the notification does, so no screen changed. The service starts only while the app is in front,
  since Android grants a service location only when it starts there; a walk started before location
  was allowed begins recording the next time the app is in front. A recording cut off by process death
  or reboot ends its walk at its last point and turns the mode off at the next start, told apart by a
  mark the service keeps while it runs; a walk without location behaves as before. A fix with no
  accuracy carries none rather than Android's 0. Cost if wrong: `EndInterruptedWalk` and
  `WalkingNotifier.show`.
- 2026-09-23: **1.1.0-beta ships M1–M5, M4b and M7.** M6, walks on the map and cats per km, is the
  slice left. The release is the first signed with a release key (`docs/reference/releasing.md`).
